## Notes

### `local-fileio-windows`
- platform: Windows 11
- `PyArrowFileIO`: FAIL OSError
- `FsspecFileIO`: OK (2 rows)
- The Windows drive letter in an absolute path is parsed as a URI scheme, so every local path form fails. FsspecFileIO is therefore pinned in glassbox.catalog rather than left to inference.

### `bucket-partitioned-write`
- 4 data files written across buckets

### `day-partitioned-write`
- 3 data files (expect 3 — three distinct days)

### `scan-order-stability`
- Stable here, but this is NOT guaranteed by the spec — training must still sort explicitly before fitting.

### `copy-on-write-delete`
- Delete is copy-on-write: whole data files are rewritten.

### `delete-rewrite-blast-radius`
- 1/4 files rewritten for a single-row delete — this is why features.* is bucketed on subject_id.

### `expire-snapshots`
- API surface: `table.maintenance.expire_snapshots().by_ids([...]).commit()`
- snapshots 3 -> 1; data files 3 -> 3
- METADATA-ONLY: orphaned data files remain on disk. Erasure must unlink them explicitly (fallback tier 2 in the risk register).

### `arrow-ns-timestamp`
- Rejected as expected: UnsupportedPyArrowTypeException

### `arrow-large-string`
- Rejected as expected: UnicodeEncodeError
